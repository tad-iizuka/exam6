# mini_serv 課題

**課題名**: mini_serv
**提出ファイル**: mini_serv.c
**使用許可された関数**: write, close, select, socket, accept, listen, send, recv, bind, strstr, malloc, realloc, free, calloc, bzero, atoi, sprintf, strlen, exit, strcpy, strcat, memset

---

127.0.0.1 の特定のポートでクライアントの接続を待ち受け、クライアント同士がやり取りできるようにするプログラムを作成せよ。

このプログラムは、バインドするポート番号を第一引数として受け取る。
引数が与えられなかった場合は、標準エラー出力に "Wrong number of arguments" と出力し、続けて改行(\n)を出力してステータス1で終了すること。
接続を受け付け始める前にシステムコールがエラーを返した場合は、標準エラー出力に "Fatal error" と出力し、改行(\n)を出力してステータス1で終了すること。
メモリを確保できなかった場合も同様に、標準エラー出力に "Fatal error" と出力し、改行(\n)を出力してステータス1で終了すること。

プログラムはノンブロッキングでなければならないが、クライアントが怠惰でメッセージを読まなかったとしても、そのクライアントを切断してはならない……

プログラムに `#define` プリプロセッサを含めてはならない。
プログラムは 127.0.0.1 のみを待ち受けること。
渡される fd は、select を呼び出す前に recv や send を呼ぶとブロックするように設定されているが、それ以外の場合はブロックしない。

## クライアントがサーバーに接続したとき

- そのクライアントには id が割り当てられる。最初のクライアントは id 0 を受け取り、以降新しいクライアントは直前のクライアントの id + 1 を受け取る。
- `%d` はこの番号に置き換えられる。
- サーバーに接続している全クライアントに次のメッセージが送信される:
  ```
  server: client %d just arrived
  ```

## メッセージの送受信

クライアントはあなたのプログラムにメッセージを送信できなければならない。

- メッセージは印字可能文字のみで構成される(チェックの必要はない)。
- 1つのメッセージに複数の `\n` が含まれる場合がある。
- サーバーがメッセージを受信したら、他の全クライアントに対し、各行の先頭に `"client %d: "` を付けて再送信しなければならない!

## クライアントがサーバーから切断したとき

- サーバーに接続している全クライアントに次のメッセージが送信される:
  ```
  server: client %d just left
  ```

## 注意事項

メモリリークや fd リークは禁止する。

補助として、サーバーの雛形が書かれた main.c が用意されている(役立つ関数も含まれているかもしれない)。ただし、このファイルには使用禁止の関数が使われていたり、最終的なプログラムに含めてはならない記述があったりするので注意すること。

> **警告**: テスターは、あなたのプログラムができるだけ速くメッセージを送信することを期待している。不必要なバッファリングをしないこと。

評価にはいつもより少し時間がかかる場合がある……

## ヒント

- nc(netcat)を使ってプログラムをテストできる。
- nc を使ってプログラムをテストすべきである。
- テストには `fcntl(fd, F_SETFL, O_NONBLOCK)` を使ってもよいが、select を使用し、EAGAIN のチェックは絶対に行わないこと(`man 2 send` 参照)。
